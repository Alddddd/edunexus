# EduNexUs UI Direction

## Current UI Phase

EduNexUs is now in:
- Governance + Verification Infrastructure Stabilization
- Institutional Settlement Lifecycle Polish
- Advanced Morph Verification Console Stabilization

This file documents the stabilized direction after the recent UI/UX, governance validation, settlement lifecycle, and audit verification upgrades.

Important:
- This is not a redesign brief.
- Do not redesign the shared shell/layout unless fixing a real UX issue.
- Preserve the current MVP workflow and protected operational systems.
- Continue presenting EduNexUs as institutional reimbursement and verification infrastructure, not a crypto product.

---

## Product Feel

Current visual direction:

```text
Institutional Sage Fintech
```

The interface should feel:
- premium
- modern
- institutional
- fintech-inspired
- cooperative-aware
- governance/audit oriented
- operationally realistic
- calm and readable
- demo-ready without feeling theatrical

Avoid:
- crypto-trader aesthetics
- cyberpunk styling
- gaming UI
- wallet-first language
- excessive animation
- neon/glow blockchain motifs
- visual clutter
- unnecessary gradients
- marketing-page patterns inside dashboards

## Shared Shell Standard

Primary shared shell:
- `resources/views/layouts/dashboard.blade.php`

The shared dashboard shell includes:
- desktop persistent sidebar
- mobile/tablet collapsible sidebar drawer
- hamburger menu
- backdrop close
- Escape close
- responsive topbar controls
- responsive notification dropdown sizing
- Alpine-powered responsive behavior

Animations:
- restrained sidebar slide/fade
- backdrop fade
- subtle hover transitions
- no heavy animation libraries
- no opacity animation on dense text cards if it risks flicker

Icon standardization:
- reusable SVG icon component
- used across sidebar, notifications, logs, blockchain states, settlement states, dashboard indicators, workflow arrows, toasts, and modals

## Governance Rule Validation UI

Merchant validation should present backend checks as understandable governance decisions.

Rule validation UI should:
- lead with an overall eligibility result
- show pass/fail governance cards
- explain failed checks in plain language
- keep raw rule keys subtle as audit metadata only
- block processing visibly when any rule fails
- avoid developer-oriented wording

Preferred labels:
- Claim reference verified
- Approval status confirmed
- Claim validity active
- Merchant eligibility verified
- Redemption availability confirmed
- Approved amount validated

Motion guidance:
- hover shadow/lift is acceptable
- avoid opacity animations on detailed rule cards
- text must never disappear during scroll
- respect `prefers-reduced-motion`

## Settlement Lifecycle UI

Settlement surfaces should feel like institutional reimbursement infrastructure.

Use lifecycle language:
- Ready for Release
- Released
- Settlement Generated
- Settlement Released
- Settlement audit-ready

Avoid implying:
- real crypto payment transfer
- stablecoin settlement
- wallet movement
- token payout

Settlement UI should show:
- merchant
- member/program context
- amount visibility
- lifecycle progress
- release timestamp when available
- linked proof/audit status when available

## Advanced Morph Verification Console Direction

The Morph Verification Console should feel like a governance and audit verification dashboard, not a crypto explorer clone.

It should show:
- verification status
- proof integrity labels
- validation summary
- lifecycle timeline
- proof bundle viewer
- proof hash
- transaction hash
- settlement status context
- member/merchant/amount metadata
- recorded timestamp

Preferred labels:
- Verified
- Proof Recorded
- Integrity Valid
- Validation Passed
- Pending Verification
- Integrity Warning
- Audit-ready

Explanation direction:
- Morph records tamper-resistant proof receipts for assistance validation and settlement events.
- Keep this explanation restrained and institutional.

Avoid:
- hacker aesthetics
- chain hype language
- fake cryptographic claims
- pretending wallet/on-chain verification exists when it does not
