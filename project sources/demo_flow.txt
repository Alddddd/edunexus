# CoopFund Nexus — Demo Flow

## Purpose

This document defines the exact demo/video flow for CoopFund Nexus.

The demo must show:
- the real-world problem
- the solution
- the core workflow
- QR verification
- programmable assistance validation
- Morph blockchain proof
- dashboard update

The demo should feel:
- clear
- fast
- polished
- realistic
- product-like

---

# 1. DEMO STYLE

The demo should be a:

# clean product walkthrough

NOT:
- thesis defense
- long PowerPoint lecture
- overly technical blockchain explanation

Recommended style:
- screen recording
- voice-over narration
- clean cuts
- simple transitions
- short text overlays

---

# 2. IDEAL DEMO STRUCTURE

## Total Length

Target:
```text
1.5 to 2 minutes
````

Keep it short, clear, and direct.

---

# 3. DEMO SEQUENCE

## Part 1 — Problem Introduction

### Target: 10–15 seconds

Message:

```text
Many Philippine cooperatives still rely on manual records and fragmented settlement processes, making financial assistance verification difficult to audit and prone to disputes.
```

Visuals:

* quick dashboard preview
* assistance request list
* settlement screen preview

---

## Part 2 — Solution Introduction

### Target: 10–15 seconds

Message:

```text
CoopFund Nexus is a web-based cooperative assistance and merchant settlement platform powered by QR verification and Morph blockchain proof.
```

Visuals:

* landing/dashboard screen
* short workflow preview

---

## Part 3 — Admin Approves Assistance

### Target: 20 seconds

Show:

* admin dashboard
* pending assistance request
* approve request
* approved amount
* assistance category

Narration:

```text
The cooperative admin reviews and approves a member assistance request under a programmable assistance program.
```

Visual highlight:

```text
Education Assistance
Approved Amount: ₱2,500
Allowed Merchant Category: School Supplies
```

---

## Part 4 — QR Code Generated

### Target: 10 seconds

Show:

* generated QR code
* claim/reference code
* request status changed to Approved

Narration:

```text
Once approved, the system generates a QR claim code that the member can present to an authorized partner merchant.
```

---

## Part 5 — Merchant Scans QR

### Target: 20 seconds

Show:

* merchant portal
* QR scan or manual reference search
* claim details appear

Narration:

```text
The merchant scans the QR code and the system checks if the claim is valid.
```

Validation checks shown:

```text
Merchant category: Valid
Status: Approved
Amount: Within limit
Duplicate claim: None
Expiration: Valid
```

---

## Part 6 — Programmable Rules Validate Claim

### Target: 15 seconds

Show:

* validation success screen
* claim confirmation

Narration:

```text
Programmable rules make sure the assistance can only be used at approved merchants and within the approved amount.
```

This is one of the main wow moments.

---

## Part 7 — Morph Blockchain Proof

### Target: 20 seconds

Show:

* transaction processing
* transaction hash
* verified status
* blockchain log entry

Narration:

```text
After the claim is confirmed, Morph blockchain records a tamper-resistant proof of the transaction.
```

Visual highlight:

```text
Verified on Morph Blockchain
Transaction Hash: 0x...
Status: Confirmed
```

This is the strongest blockchain moment.

---

## Part 8 — Dashboard Updates

### Target: 15 seconds

Show:

* dashboard analytics updated
* total approved assistance
* total claims
* settlement status
* blockchain verification count

Narration:

```text
The dashboard updates automatically, giving the cooperative and auditors a transparent view of assistance releases, claims, and merchant settlements.
```

---

## Part 9 — Closing Impact

### Target: 10 seconds

Message:

```text
CoopFund Nexus helps cooperatives modernize financial assistance and merchant settlements through transparent, programmable, and blockchain-backed verification.
```

Visuals:

* dashboard final view
* blockchain logs
* project name/logo

---

# 4. MAIN WOW MOMENTS

The demo must emphasize:

```text
1. Admin approval workflow
2. QR claim generation
3. Merchant QR verification
4. Programmable validation rules
5. Morph blockchain transaction hash
6. Dashboard analytics update
```

---

# 5. WHAT NOT TO OVEREXPLAIN

Avoid spending too much time on:

* smart contract internals
* Solidity code
* gas fees
* wallet mechanics
* database tables
* authentication system

The demo should focus on:

# working product experience

---

# 6. VOICE-OVER STYLE

Voice-over should be:

* calm
* confident
* clear
* professional
* easy to understand

Avoid:

* too much jargon
* rushed explanations
* overly technical language

---

# 7. TEXT OVERLAY SUGGESTIONS

Use short overlays like:

```text
Programmable Assistance Approval
QR-Based Claim Verification
Morph Blockchain Proof
Tamper-Resistant Settlement Log
Real-Time Dashboard Update
```

---

# 8. VIDEO EDITING STYLE

Editing should be:

* simple
* clean
* fast-paced
* not overdone

Use:

* clean cuts
* short fades
* zoom-in highlights
* cursor focus
* simple captions

Avoid:

* distracting effects
* excessive animations
* meme edits
* long pauses

---

# 9. FINAL DEMO PRIORITY

The demo should make judges think:

```text
This is practical.
This is understandable.
This uses blockchain meaningfully.
This could realistically be deployed.
```

That is the target impression.
